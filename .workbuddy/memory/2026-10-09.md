## v1.0.13 修复（13:08 用户反馈截图：text 池日志「用户请求」列全空）

### 根因
- 1.0.12 只在媒体端点（serveAutoImage/serveAutoVideo）用 `mustJSON(body)` 填了 user_request；

- `opts := relay.Options{... Body: rawBody}`（加注释说明 Body 仅用于日志，实际转发由 BodyFor 生成，relay.Do 中 BodyFor 非 nil 时优先，故不影响请求本身）。
- 编译干净（build_exit=0，仅 GOPATH/GOROOT 警告）；web e2e 的失败（TestNeverLeaks429UnderBurst/TestAutoRoutesText 等 `模型 agnes-auto 不是 chat 模型`）经 `git stash` 基线对比确认为既有问题，与本次无关。

### 审计结论（代码编写 / 自动工具调用 / 方案生成 场景，8 免费号）—— 收益排序
**收益最大（已在本轮或 v1.0.15 落地）**：
1. 热路径异步落盘（ChargeKey/AppendUsage/Bind）：多任务并发下消除每请求 2~3 次同步 Open/Write/Close 的尾延迟 —— 这是 WorkBuddy 高频调用时体感「卡」的主因。
2. 情景模式「多任务并行」：QueueMaxSize 500 / QueueMaxWait 180000ms / RetryCap 12000ms + 两级队列，让「写代码 + 自动工具 + 方案」同时挂多个任务时不被排队超时打断。
3. 两级队列：文本池内非流式（工具/短调用）优先于流式（长生成）领槽 —— 代码工具调用多是短促非流式，优先出队正好贴合。
4. 粘性会话头修复：同一 coding 会话固定落同一账号（上下文/KV 亲和），避免换号后「模型行为漂移」。

**已具备、无需再动**：意图缓存 LRU（O(1) 命中）、单账号并发信号量、连接池自适应、429 单 pacer reload。

**剩余可做（低优先 / 需权衡，未做）**：

### 429 网关内自动重试（不透传、不中断客户端在途任务）
- `config.Settings` 加 `RateLimitRetryMax`（默认 6）/ `RateLimitWaitBudgetMS`（默认 180000=3min）；归一化只对**负数**兜底（0 保留特殊语义：RetryMax=0 沿用普通 RetryMax、WaitBudget=0 不限等待），不破坏 0 语义。

- `sudo_pty` 写法：`chan.get_pty(); chan.exec_command("sudo -S "+cmd); chan.send(PW+"\n")`，轮询 `exit_status_ready()`（带 40s 超时防挂）。
- 经验固化：**fnOS 热更 = 停服(pkill+普通 stop) → 普通 cp 替换 → PTY sudo appcenter-cli start**；纯非 PTY sudo 会挂死，普通 appcenter-cli 会 broker panic。

## v1.0.22：网关执行效率优化（#29）+ 清理 content_policy 死代码

### 背景（用户决策）
- v1.0.21 加的「forward 下全局剥离 <content_policy>」实测是死代码：server.go:614 仅在 `policy != "" && policy != "forward"` 才调 ApplySystemPromptPolicy，线上 forward 不触发 → 从未生效。
- 用户方向调整：基于 RawCapture 实测（下游提交的 ~500KB 数据基本都有用），**不去除 WorkBuddy 绝大部分内容**，在此前提下提升执行效率。决策：①移除死代码；②P0 前缀缓存 + P1 请求体 gzip 一起做。

### 实现（内容零改动、内容保持不变）

  * `upstream_request_gzip`（P1）：发往上游的请求体做 gzip 压缩（Content-Encoding: gzip），削减网关→上游 ~500KB 带宽到 1/5~1/8；**需上游支持解压 gzip 请求体，否则 400**，故默认关。

- `relay.go`：`attemptOnce` 在构造请求前先做 P0/P1 变换（transform 落在对外的 `body` 参数作用域，非 Do）；新增 `gzipBytes`（compress/gzip）+ `addAnthropicCacheControl`（仅改顶层 string/array system，OpenAI 风格 system 在 messages 内安全 no-op）；gzip 时 `req.Header.Set("Content-Encoding","gzip")`，Content-Length 由 Go 按压缩后字节自动设。
- `config.go` 移除 v1.0.21 死代码（stripContentPolicyGlobally/stripTagBlock/regexp import、ApplySystemPromptPolicy 恢复 forward 早返干净形态）；`systemprompt_test.go` 删除对应孤儿测试 + 去掉多余的 `strings` import。
- `nas_op.py` 新增 `setopt <key> <on|off>` 通用开关（复用 PTY sudo 读/改/写 settings.json + 重启），用于远端切换新设置。
