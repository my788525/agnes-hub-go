## 效率评估 + 一批修复（v1.0.25）

用户三问：①gzip 是否真提效/提多少 ②还有没有别的提速办法 ③去掉 content_policy 是否值得/更费时。
- 实测（网关同款 compress/gzip，~500KB 体）：gzip 压缩 CPU 仅 1~2ms/请求、可忽略；压缩比重复度高时 99%+、真实 WorkBuddy 包典型 70~90%，省的是**字节传输**不是 CPU。结论：上游是远端(WAN)则 gzip 值得开，局域网则收益微乎其微但无害。
- **更正 v1.0.24 记忆里的误判**：TestChineseAccountNameDoesNotBreakHeaders 的根因**不是**"存量无关问题"，而是两处：
  1. v1.0.23 把 UpstreamRequestGzip 默认置 true 后，**web mock 测试桩**（newMockAgnes.handler）直接 ReadAll+Unmarshal 不解压 gzip，把压缩体当明文解析出空 payload→model=""→400（真实上游 agnes 能解压、GZ=200，线上无此问题）。修 mock 桩支持 gunzip（新增 readGzipAwareBody，感知 Content-Encoding: gzip）。
  2. **IsAutoModel("agnes-auto") 漏判**：autoNames 只含 auto/auto-all 且前缀匹配 auto，agnes-auto 以 agnes 开头不被识别为 auto→被当显式模型名原样透传上游→400。而 config.AutoModelName 默认值就是 "agnes-auto"（config.go 默认）+ 控制台聊天页默认也发 agnes-auto，逻辑自相矛盾。修法：把 agnes-auto 加进 IsAutoModel 的 autoNames。
  两处叠加让 web 包一批 e2e 全绿。
- 效率/省 token 改进（v1.0.25）：
  - 新增可开关 `strip_content_policy`（默认关）：转发前用正则 `(?s)<content_policy>.*?</content_policy>` 纯字节替换剥离客户端注入段，省 token 而非省速度（实测替换 ~0.1ms/请求，远轻于 gzip 1ms），不伤 user_query 真实输入。走 setopt 运维通道（与 gzip 一致，不进 console UI）。
  - 上游连接池 IdleConnTimeout 90s→5min（agentic 编码任务两轮间隙常 >90s，避免 idle 连接被回收后下轮重建 TLS）。
  - 清理 relay.Do 循环后不可达死代码 + 冗余 last 变量，移除多余 errors import，go vet 归零。
- **澄清**：P0 addAnthropicCacheControl 早已有 `opts.Anthropic` 守卫（relay.go），agnes 主路径（OpenAI 风格、system 在 messages 内）本不跑其 JSON round-trip，无"1ms 浪费"，本版未改（避免虚改）。
- 验证：BUILD=0 / VET=0；intent+relay+web 三套全 PASS；新增 TestContentPolicyReStrips PASS。NAS 热更 v1.0.25，healthz ok、7 账号全可用、0 panic。仅推 master，未打 fpk/Release。
- gzip 决策：用户此前要求"改为压缩优化每次 workbuddy 提交上来的包"，故保留默认开；本次修的是测试桩，不是回退 gzip。

## v1.0.26：全部落地（日预算 + 路由分层 + JSON 安全剥离 + 数组归一化）

用户明确"全部落地"并两次催"请继续执行任务"（期间线上日志出现 400 unexpected end of JSON input）。本版把此前中断/未提交的一整批改动收口：

- **JSON 安全剥离（修复线上 400 回归）**：v1.0.25 把 strip_content_policy 默认开，但用的是朴素正则 `(?s)<content_policy>.*?</content_policy>` 纯字节替换——一旦开合标签落在不同 JSON 字符串字面量（如开标签在 messages[i].content、闭标签在 messages[j].content）就会把中间整段删掉，破坏 JSON 结构，上游报 `invalid character '{'` / `unexpected end of JSON input` 400。v1.0.26 改为 `stripContentPolicy` + `jsonStringSpans`（转义感知的 JSON 字符串区间扫描），**只在匹配的 <content_policy> 段完全落在单个 JSON 字符串字面量内时才删**，`json.Valid` 兜底返回原 body。新增 TestStripContentPolicyCrossString 专门锁这个回归。
- **strip_content_policy 默认开启**（config 默认 true），省 token（高轮次会话每轮重复 ~100~400 词），对 user_query 真实输入与其他字段零改动；可 setopt 关。
- **日预算 + 路由分层（用量型账号支持）**：
  - `daily_budget`（<=0 退回旧 RPM 行为，对 agnes 零影响）：账号累计用量达上限当天自动退出候选池，次日 RollDailyBudgets 回池。
  - `routing_mode`（rate_first/budget_first/balanced）+ `budgetTier`：决定用量型与速率型账号的消耗优先级。
  - `ChargeBudget` 解析 OpenAI 兼容响应的 `usage.neurons`（Cloudflare 计费字段），仅对配了 daily_budget 的用量型账号记账；其他上游无该字段返回 0，恒 no-op。
- **OpenAI 路径 content 数组→字符串归一化**（normalizeContentArray + flattenTextBlocks）：仅对纯文本块生效，含 image_url 等非文本块时保留原数组，对其他上游零影响。
- **测试**：新增/改写 5 个回归（TestStripContentPolicy、TestStripContentPolicyCrossString、TestStripContentPolicySameStringSafe、TestNormalizeContentArray、TestNormalizeContentArrayKeepsImages）。
- **验证**：BUILD=0 / VET=0 / relay+config+hub 全 PASS；交叉编译 linux-amd64 热更到 fnOS NAS（192.168.100.3:4142），healthz 确认 version=1.0.26、ok=true、panics_total=0，远端二进制 grep jsonStringSpans 命中 1（确认 JSON 安全剥离已上线，线上 400 风险消除）。
