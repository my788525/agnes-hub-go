## 2. 生产「渐变卡死、无报错、重启才好转」根因与修复
用户报：网关起初正常，逐渐等待非常久、无进度无报错，停了再开才恢复。
- 根因：客户端在流式首字节到达前断开（用户「停止」再继续）时，`web/server.go` 的 `proxy()` 流式分支 `case <-ctx.Done():` 直接 `return`，**无人消费后台 `relay.Do` 推入带缓冲 `ch` 的 `*Result`** → 其上游连接 + 并发信号量槽位永久泄漏。首选账号 sem 占满后所有请求卡在 `Acquire` 无限等待，只有重启能恢复。
- 修复：两处 `ctx.Done()` 都改为「起 goroutine 把 `ch` 里的 result 取出来 `Close()`（释放上游连接 + 信号量槽位）」：
  - 首字节等待窗口（原 1326 处 select）。
  - **心跳等待窗口**（1356 心跳循环 1387 处）——稳态长等待路径，比首字节窗口更易触发，原漏修，本次补上。
- 验证：`TestNeverLeaks429UnderBurst` 等 web 全绿；`go build ./...` 通过。
- 注：本次跑 `go test` 首次出现「测试超时」是冷启动偶发抖动（原始版连跑 3 次稳定 ~25s，我的改动连跑 3 次也稳定 ~25s；首个 60s 超时是编译后首跑异常），非回归。
